あらまし 近年の⽣成 AI の進展により， Text-to-3D 技術は⾶躍的な視覚的品質を達成したが，既存⼿法はレンダリ ング画像の「⾃然さ」を優先するため，物理的・⼯学的整合性を⽋く問題（提案する枠組みでは幾何学的ハルシネー ションと定義する）が未解決の課題となっている．実施した研究では，幾何学的ハルシネーションという課題に対し， Model Context Protocol (MCP) を基盤とした⾃律的品質保証フレームワークを提案する．提案⼿法は， LLM と 3D 環境（ Blender ）を接続し，視覚情報ではなく数値データ（座標，法線，⼨法）に基づいてモデルを直接検査・修正す る「⽣成・検査・修正」サイクルを⾃律的に実⾏する．システムは，不変の「規制知識」と適応的な「経験知識」から なる⼆層知識構造を有し，過去の修正プロセスから効率的な⽅策を獲得する知識継承メカニズムを備えている．建築 制約を持つ⽣成タスクにおける評価実験の結果，提案⼿法は視覚ベースでは困難な厳密な制約充⾜を達成した．さら に，性能推移の分析により，知識の蓄積が⾃律性スコアを最⼤値の「 5 」まで向上させ，初期試⾏と⽐較してトークン 消費量を約 58% 削減することを定量的に実証した．提案するアプローチは， 3D ⽣成の評価軸を主観的な「⾒た⽬」か ら客観的な「構造的整合性」へと拡張し，エンジニアリングツールとしての⽣成 AI の可能性を拓くものである．

[chunk 3 / page 1]
近年，⽣成 AI 技術の進展は⽬覚ましく，テキストから画像， 映像，そして 3D モデルを⽣成することが⽇常的な技術となりつ つある．特に⼤規模⾔語モデル（ LLM ）を⽤いた「 3D-GPT 」 [1] のようなプロシージャル⽣成フレームワークは，専⾨的なスキ ルを持たないユーザでも複雑な 3D シーンを構築できる可能性 を切り開いた．しかし，既存の Text-to-3D 技術が⽣み出す成 果物は，レンダリング画像としての視覚的な「⾃然さ」におい て優れている⼀⽅で，構造的な「整合性」や物理的な「妥当性」 において致命的な⽋陥を抱えることが多い．

[chunk 4 / page 1]
例えば，⽣成された建築モデルにおいて，ドアが床から数セ ンチ浮遊していたり，窓が壁の厚みに埋没していたり，あるい は階段の段差が不均⼀であったとしても，特定のアングルから の静⽌画では成⽴して⾒えることがある．提案する枠組みで は，レンダリング画像 I においては視覚的な違和感が⽣じない ものの， 3D 空間上の幾何学的制約 C （例：接地性 Z min = 0 ， ⾮⼲渉性 V overlap = 0 ）を満たさない状態（ C ( S ) = False ）を 「幾何学的ハルシネーション」と定義する．幾何学的ハルシネー ションは， 2D 画像への射影過程で情報が⽋落するために⽣じ る， Vision Language Model (VLM) 等の視覚ベース評価では 原理的に検出困難なエラーである．

幾何学的ハルシネーションが⽣じる根源は，現在の⽣成パラ ダイムが CLIP スコア [2] や LPIPS[3] といった「視覚的評価」 に過度に依存している点にある． VLM は画像の類似性を判断

[chunk 5 / page 1]
できても， 「垂直性」 「接地性」 「包含関係」といった 3D 空間特 有の厳密な幾何学的制約を， 2D 画像から正確に逆推論するこ とは本質的に困難である．

[chunk 6 / page 1]
実施した検証の⽬的は，建築制約を持つ屋内 3D シーン⽣成 において，視覚情報に依存せず，数値データに基づく厳密な検 査のみを⽤いた⾃律的品質保証フレームワークを構築すること である．特に，静的な法規制を格納する StaticDB と，動的な 経験知識を蓄積する DynamicDB を分離・統合するアーキテ クチャにより，幾何学的整合性の保証と，試⾏回数の削減によ る推論コストの最適化を同時に達成することを，定量的に実証 する．

[chunk 7 / page 2]
⼈間が瞬時に感じる「違和感」を， AI はいかにして検知し， 修正すべきか．提案する⼿法では，⼈間が瞬時に感じる違和感 を AI が数値的に検知し修正するという課題に対し「視覚」で はなく「数値」に基づく決定論的なアプローチを提案する．具 体的には， Model Context Protocol (MCP) [4] を介して LLM を 3D モデリング環境（ Blender ）に直接接続し，エージェント が 3D 空間を座標や⼨法といった「数値データ」として認識・ 操作するアーキテクチャを構築する．

提案システムの特徴は，書き換え不可能な規制知識を扱う StaticDB と，ユーザからのフィードバックを通じて成⻑する経 験知識を扱う DynamicDB を分離した⼆層知識モデルにある．

[chunk 8 / page 2]
エージェントは，物理法則や建築基準法といった絶対的なルー ルを遵守しつつ，対話を通じて得た修正指⽰を新たなルールと して知識ベースに蓄積する．知識の永続化により，セッション ごとに記憶がリセットされる従来の LLM エージェントの限界 を克服し，使い込むほどに⽂脈理解が深化し，推論コストが最 適化される「経験を蓄積するパートナー」としての AI を実現 する．

[chunk 9 / page 2]
実施した検証の主な貢献は以下の 2 点に集約される．本質的 に，提案⼿法は Text-to-3D という特定のドメインに留まらず， 「数値的に検証可能な⽣成タスク⼀般」に対して適⽤可能な，普 遍的な品質保証原理を⽰唆している．

数値検査に基づく MCP ループの構築 : 視覚的評価 （ VLM ） を完全に排除し， MCP を介して 3D 座標・法線データを 直接検証するループを実装した点．数値的な検証により， 画像ベースの⼿法では検出不可能なオクルージョン領域や 微細な位置ズレの修正を可能にした．

⼆層知識構造による探索の効率化 : エージェントの知識を 不変の「規制」と可変の「戦略」に分離し，修正プロセスで 得た成功パターンを永続化するメカニズムを実装した点． 経験の蓄積により，初期のランダムな探索から，知識検索 による即時解決へと⾏動を変容させることが可能となった．

[chunk 10 / page 2]
第 2 章では， Text-to-3D 技術における評価指標の変遷と課 題，および⼤規模⾔語モデル（ LLM ）を⽤いた 3D 操作に関する 最新の研究動向を概観する．特に，既存の視覚ベースのフィー ドバックループが抱える限界を指摘し，提案するアプローチが 採⽤する MCP を⽤いた構造的検証アプローチの優位性と学術 的位置付けを明確にする．

[chunk 11 / page 2]
3D コンピュータビジョンとグラフィックスの分野は，深層学 習の導⼊により劇的な変⾰を遂げている．初期の 3D ⽣成モデ ルは，点群やボクセル，メッシュといった明⽰的な 3D 表現を 直接⽣成することを⽬的としており，初期の 3D ⽣成モデルの 評価には Chamfer Distance (CD) や Earth Mover's Distance (EMD) といった幾何学的距離指標が標準的に⽤いられてき た [5], [6] ．幾何学的距離指標は，⽣成された形状と正解データ との間の物理的な距離を測定するため，幾何学的な忠実度を保 証する上では⼀定の有効性を持つ．しかし， CD は点密度の不 均⼀性に鈍感である「不感領域」の問題を抱え， EMD は計算 コストが⾮常に⾼いという実⽤上の課題があった．

[chunk 12 / page 2]
その後， Neural Radiance Fields (NeRF) [7] や 3D Gaussian Splatting (3DGS) [8] の登場により，パラダイムは「画像から の逆投影」による⽣成へとシフトした．⽣成パラダイムのシ フトに伴い，評価指標も PSNR ， SSIM ，そして LPIPS[3] や CLIP Score[2] といった画像空間での知覚的類似性指標が主流 となった．特に LPIPS は⼈間の知覚と⾼い相関を持つとされ

るが，画像空間での知覚的類似性指標は本質的に「 2D の⾒た ⽬」を評価するものであり， 3D 構造としての整合性を保証し ない．

例えば，ある視点からは整合して⾒えるが，裏側が⽋損して いる，あるいは物体同⼠が物理的に不可能な交差をしていると いった問題（ 2D チーティング）は，画像ベースの指標では検 出困難である [9] ．建築やプロダクトデザインのようなエンジニ アリンググレードの整合性が求められる領域において，画像空 間での指標のみを追求する指標は不⼗分であり，構造的な「妥 当性」を担保する新たな枠組みが必要とされている．

[chunk 13 / page 2]
LLM の⾼い推論能⼒を活かし，エージェントとして 3D 空間を操作させる試みも始まっている．代表的な研究である SceneCraft [10] は， ユーザの⾃然⾔語指⽰を Blender の Python スクリプトに変換し， Python スクリプトの実⾏結果をレンダ リング画像として取得，マルチモーダル LLM (MLLM) で解析 することで修正ループを回す⼿法を提案した． SceneCraft によ るアプローチは，プログラマティックな操作により幾何学的構 造をある程度制御できる点で画期的である．

しかし， SceneCraft 等の既存⼿法は「視覚フィードバック」 に依存しているため， VLM の空間認識能⼒の限界に縛られる という課題がある．視覚情報は 3 次元情報の 2 次元への圧縮 （射影）であり，そこから完全な 3D 構造を復元・評価すること は逆問題として本質的な不安定さを孕んでいる．例えば， 「物 体が床から数ミリ浮いている」といった微細な誤差や， 「壁の内 部に配管が正しく通っているか」といったオクルージョンの検 証は， 2D 画像からは原理的に不可能に近い．

[chunk 14 / page 2]
したがって，正確な 3D モデリングを実現するためには，視 覚情報に頼らない，シーンデータ（頂点座標，法線ベクトル， バウンディングボックス等）への直接的なアクセスと，数値に 基づく論理的な検証が必要となる．

[chunk 15 / page 2]
Anthropic によって導⼊された MCP[4] は， AI モデルと外部 ツール間の通信を標準化するオープンプロトコルであり，エー ジェントシステムの実装に⾰新をもたらしている．従来の関 数呼び出しが単発の関数実⾏を⽬的としていたのに対し [11] ， MCP はクライアント・サーバ間のステートフルな接続を維持 し，リソースの購読やプロンプトのテンプレート化，そして何 より「 Sampling 」プリミティブによる双⽅向のインタラクショ ンをサポートしている点が MCP の特徴である．

「 Sampling 」機能は，サーバ側（ツール側）からクライアント （ LLM ）に対して，コンテキストを与えた上で次の⾏動を能動的 に問い合わせることを可能にする． Sampling 機能により，エー ジェントは⾃⾝の⾏動結果（ツールの出⼒やエラーメッセージ） を受け取り，⾏動結果を評価して次の⾏動を決定する⾃律的な ループ（ ReAct サイクル [12] や⾃⼰修正ループ [13], [14] ）を， 標準化されたプロトコル上で堅牢に実装可能となる．

[chunk 16 / page 3]
既存の UnrealMCP[15] などの実装は，⾃然⾔語によるコマ

ンド実⾏を可能にしたが，体系的な評価フレームワークや，失 敗から学ぶ⾃⼰改善ループまでは実装されていないのが現状で ある．

実施した検証では，体系的な評価フレームワークや⾃⼰改 善ループが実装されていないという「研究の空⽩領域」に着 ⽬する．具体的には， MCP の双⽅向性を活かし，視覚ではな く数値データに基づく厳密な検査をループに組み込むことで， SceneCraft の課題であった精度の問題を解決する．さらに，知 識グラフ上の推論に着想を得た DynamicDB による知識継承 メカニズムを MCP サーバ内に実装することで，セッションを 超えて経験を蓄積し，適応的に成⻑するエージェントアーキテ クチャを提案するものである．⼆層知識構造は，単なる⾃動化 ツールを超え，設計者の意図と法的な制約を調停するパート ナーとしての AI の実現に向けた重要なステップとなる．

第 3 章では， 3D モデリングにおける構造的な整合性の担保 と，経験に基づく適応的な戦略獲得を実現するためのシステム アーキテクチャ「 Dual-Knowledge MCP Architecture 」につ いて詳述する．提案した構成の中核は，推論能⼒と実⾏環境を 標準プロトコルで疎結合に接続し，静的な規制知識と動的な経 験知識という性質の異なる⼆つの知識源を統合的に運⽤する点 にある．

提案システムの設計思想は， ⾼度な推論を⾏う AI コア （ LLM ） と，物理的なシミュレーションを⾏う 3D 環境（ Blender [16] ） を明確に分離し， AI コアと 3D 環境の間を標準化されたイン ターフェース（ MCP ）で調停することにある． MCP を⽤いた 疎結合な設計により，特定の LLM や 3D ソフトウェアに依存 しない拡張性と，各コンポーネントの独⽴した進化を担保して

システムの全体的な概念図を図 1 に⽰す．アーキテクチャは 主に 4 つの論理階層によって構成される．

[chunk 21 / page 3]
システムの頭脳にあたる AI コア層では，ローカル環境等のセ キュアなインフラ上で運⽤可能な「 gpt-oss:20b 」 [17] を採⽤す る． gpt-oss:20b は 200 億パラメータを持つオープンウェイト の MoE （ Mixture-of-Experts ）モデルであり，軽量ながら⾼い 推論能⼒と指⽰追従性を有している． LLM は単なるテキスト ⽣成器としてではなく，ユーザの意図を解釈し，ユーザの意図 を達成するためのタスクをサブゴールに分解する「プランナー」 として機能する． 「段階的な推論を促すプロンプト設計」 [18] を 通じて，現状認識，知識参照，⾏動計画の策定という⾼次の推 論プロセスを実⾏する．

[chunk 22 / page 4]
AI コアからの抽象的な指⽰を，具体的な計算処理や 3D 操作 に変換する中間層である． MCP ルーターはリクエストを受け 取り，適切なツールモジュールに振り分ける． MCP 統合層に は， 3D オブジェクトの⽣成・操作（ T1, T2 ） ，シーンの幾何学 的検証（ T3 ） ，そして経験知識の蓄積・検索（ T4 ）といった機 能が，標準化された MCP ツールとして実装されている．標準 化されたツールの実装により， LLM は下位層の複雑な API を 意識することなく，関数呼び出しの形式で環境に介⼊できる．

[chunk 23 / page 4]
提案⼿法の最⼤の独⾃性は，エージェントが参照する知識 ベースを，性質の異なる⼆つのストレージに分離・統合した点 にある（図 1 ：知識層） ．

[chunk 24 / page 4]
建築基準法，物理法則，あるいはプロジェクト固有の仕様書 など，絶対に変更してはならない「ハード制約」を格納する 静的なデータベースである．例えば「階段の蹴上げは 23cm 以 下」 「ドアは床に接していなければならない」といったルールが JSON 形式で定義される．規制ルールは検査ツール（ T3 ）に よって厳格に適⽤され，違反があれば即座にエラーとして検出 される．規制知識層はシステムの「法令遵守」を担保する役割 を担う．

[chunk 25 / page 4]
エージェントがタスク実⾏プロセスを通じて獲得した， 「特定 の⽂脈における有効な戦略」や「過去の成功 / 失敗パターン」を 蓄積する動的なデータベースである [19] ．経験知識はシステム の稼働に伴って成⻑する知識であり， 「ソフト制約」として機能 する．プランナーは，未知の状況に直⾯した際， DynamicDB から類似局⾯における成功事例を検索（ RAG[20] ）し，⾏動計 画の指針とする．経験知識層はシステムの「適応性」と戦略獲 得能⼒を担保する．

規制知識と経験知識の⼆重構造により，エージェントは「法 的には正しいが，⽂脈的に不適切な解」を回避しつつ，効率的 に最適解を探索することが可能となる．

競合解消については，今後の検討課題である．提案⼿法が⽰し た「数値的リアリズム」の追求と知識継承モデルは，⽣成 AI を単なるクリエイティブツールから，信頼性が不可⽋なエンジ ニアリングや製造の現場で活⽤可能な⾃律システムへと昇華さ せるための重要な基盤となるであろう．
